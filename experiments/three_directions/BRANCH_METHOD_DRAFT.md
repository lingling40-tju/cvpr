# Policy-prefix branching for multi-turn VLN (methods draft)

This text is a candidate methods section for a paper pivot. It describes the
implemented experiment; it does not assert a navigation improvement. The
three-seed 128-step and full val-unseen results are pending.

## Motivation and hypothesis

In multi-turn VLN, an on-policy learner commonly starts each rollout at the
instruction's initial pose. An earlier policy may nevertheless visit a later
decision state where its first forward motion is followed by a change of
heading. We test whether concentrating RL continuations at such
policy-visited states changes held-out navigation performance. The comparison
is against GRPO rollouts from the task start, using the same episodes,
initializer, number of sampled continuations, reward, and optimizer budget.

The base policy and closed-loop interaction come from
[ActiveVLN](https://arxiv.org/abs/2509.12618). This experiment does not
introduce multi-turn GRPO itself. Policy-state recovery and shared-prefix
branching have relevant precedents in
[JOP-VLN](https://arxiv.org/abs/2607.13461) and
[Hindsight-Divergence Localization](https://arxiv.org/abs/2609.36864),
respectively; the contribution would need to rest on a demonstrated,
well-controlled effect for physical VLN decision states and an analysis of
its cause.

## Training-state construction

We read completed **R2R train** rollouts from earlier destination-only
policies, and select a replayable grouped-action prefix for each eligible
train episode. The selector finds a rollout's first forward command, then
its first subsequent turn; it retains the rollout only if that turn's
zero-based action index lies from 4 through 9. The prefix ends immediately
before that turn. We retain one prefix per episode, choose 512 unique
episodes in a deterministic order, and preserve
the underlying Parquet row, instruction, and expert sequence. No val-unseen
rollout supplies a training prefix. The 61 train and 11 val-unseen scenes have
no overlap. The 512-row curriculum and its diagnostics are generated by
`prepare_scaled_directions.py`.

At training time, each branch rollout starts a fresh simulator episode and
replays the saved action sequence before the model samples new actions.
Two independent continuations use the same sequence, so they begin at the
same physical pose and trajectory history. This implementation replays
actions in separate simulator instances; it does not fork a simulator
snapshot. The replay is training-only. Held-out evaluation starts each
episode at its ordinary initial pose, with no saved prefix.

If a prefix contains \(L\) grouped action commands, the configured generated
command budget is \(36-L\), and the configured turn budget is
\(12-\lceil L/3\rceil\). The environment's strict `>` budget check can permit
one command past the configured count. A command such as `move forward 75cm`
can execute multiple lower-level simulator steps, so these command budgets
are not equal simulator-step or GPU-compute budgets. The final training
audit reports generated and replayed command totals separately.

## Policy optimization and control

Both arms initialize from the same Qwen2.5-VL-3B SFT checkpoint. Each
optimization step uses four train episodes and two stochastic continuations
per episode. The GRPO advantage is formed within the two continuations of
each episode. The branch arm uses the policy prefix; the control arm sees the
same Parquet rows but starts from the task start because its alternative
mode is disabled and `prob_from_scrath=1`. Both use the same destination-only
reward configuration: success base 15, an additional success floor 2,
nDTW weight 0, and semantic weight 0. The actor never receives a semantic
verifier or simulator distance signal at test time.

We train 128 optimization steps for each of seeds 11, 22, and 33 on two
concurrent two-GPU lanes, then evaluate all six checkpoints on the same
fixed 256-episode val-unseen screen and the same complete 1,839-episode
val-unseen manifest. Each checkpoint receives one evaluation rollout per
episode. Per-seed paired SR and SPL changes, discordant successes, scene
bootstrap intervals, and descriptive seed variation are reported without
converting exploratory pilot results into a confirmatory claim. Full-run
audits require 512 unique train episodes, exact step-by-step episode
pairing, complete evaluator coverage, and zero inference errors.

All three 128-step training pairs and final pairing audits have now passed.
Across seeds 11, 22, and 33, branch generates a mean of 25,711 grouped
commands and replays 6,088; the from-scratch control generates 32,100.
Including replay, total commands average 31,799 versus 32,100. Mean wrapper
elapsed time is 1.84 versus 1.98 hours per run; this includes checkpoint
saving and validation and is not a GPU-hour measure. The two trajectories in
every GRPO group differ, but only 128 versus 165 of 512 groups per seed have
nonzero return variance on average. These are training-budget and reward
diagnostics, not held-out navigation effects. Exact per-seed records and the
reproducible summary are in `scale_budget/`.

## Interpretation boundary

The arm difference changes the start state, the source of history, and the
remaining command and turn budgets together. A gain would demonstrate an
effect of this combined curriculum, not isolate policy-generated prefixes
as the only cause. An equal-action-count expert-prefix dataset is prepared
for a later ablation but has not been trained. Even that comparison would
not perfectly match the physical endpoint. The pilot's scene-bootstrap
interval crosses zero, and its success differences vary across scenes; the
three-seed full evaluation is needed before making a positive claim.
The selected 512 episodes are those for which a prior policy rollout yields
the required decision-state prefix, so the training curriculum is not a
uniform sample of all R2R train episodes; the same selection is applied to
both arms of the matched comparison.
